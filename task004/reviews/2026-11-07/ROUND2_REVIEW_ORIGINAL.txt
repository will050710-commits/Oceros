**Fix before accept**

1. **The cancel handler can deadlock the CLI** (`cli.py`, `lambda *_: cancel.set()`).
   - `Event.set()` takes a non-reentrant lock, and Python runs handlers on the main thread between bytecodes. If a signal lands while the main thread is inside `Event.wait()` or `clear()`, or a second signal lands inside the first handler's `set()`, the handler blocks on a lock its own thread holds.
   - I reproduced it. Forcing the nested signal hangs with the stack in `Event.set`. With your handler copied verbatim and a lock-heavy main loop, it hung within 99 bursts of three signals.
   - A plain `wait(0.002)` loop survived about 990 bursts, so the window is narrow and depends on how `client.py` and `server.py` wait on the event. 87/87 passing doesn't rule it out.
   - Fix: replace the Event with a lock-free flag class exposing `set`, `is_set` and `wait` (`wait` polls with `time.sleep`). The same lock-heavy loop then survived 993 bursts.

2. **The SIGHUP handler defeats `nohup`.** The install loop overwrites an inherited ignore. I reproduced it: with SIGHUP ignored on entry, a SIGHUP set `cancel`. Long runs started under nohup or ssh will be cancelled when the session closes. Fix: `if signal.getsignal(number) is signal.SIG_IGN: continue`.
